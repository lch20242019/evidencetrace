# EvidenceTrace v0.1 product vertical slice

Date: 2026-07-26
Starting commit: `a0051dd62c5f4123a0e5a99929a00927b24be41d`

## Outcome

EvidenceTrace now has one bounded product path for Markdown, ADR, RFC, README,
and Markdown Git-diff auditing:

```text
Claim Miner
-> Audit Coordinator initial plan
-> citation verification or authorized Evidence Scout
-> Claim Judge
-> Audit Coordinator review plan
-> conditional Challenger
-> policy, artifacts, terminal, optional patch, and SARIF
```

This is an engineering continuation with known limitations. Phase 3 remains
`completed_with_known_limitations`, `phase4_eligible=false`, no formal
blind-holdout F1 was measured, and no new evaluation phase or dataset was
created.

## Control model

The deterministic Controller owns source access, search/fetch dispatch,
budgets, retries, state, artifacts, policy, and CI exit status. Coordinator
plans are typed and advisory. The Controller rejects unknown or duplicate
claim IDs, wrong-stage actions, citation bypass, repeated work, and
over-budget discovery.

Coordinator receives no tool. It may make at most two logical calls per
document: an initial plan and a review plan. If either call or plan fails, the
Controller records a safe fallback event and selects a deterministic plan.

Model-backed calls use the existing strict Pydantic contract and at most one
schema-only recovery. The product CLI caps provider attempts at 304. There is
no semantic repair or open-ended Agent loop.

## Agent boundaries

- Claim Miner sees one allowed Markdown paragraph. It extracts continuous
  atomic claim spans and binds local lines and paragraph citations. It does not
  see evidence or judge truth.
- Evidence Scout receives only an authorized unresolved claim and returns a
  bounded search plan. The original claim query is mandatory; new entities,
  numbers, dates, and versions are rejected. Each claim permits at most two
  queries, five candidate URLs, and three safe fetches.
- Claim Judge sees one claim and bounded evidence. It owns semantic relation,
  confidence, reason, and evidence selection, while local code owns IDs and
  source scope.
- Challenger sees the claim, Judge verdict, deterministic signals, and the same
  bounded evidence. It runs at most once for contradictions, low confidence,
  numeric/date/version facts, or comparisons and returns only `uphold`,
  `revise`, or `abstain`.

Tavily is implemented as a small `httpx` adapter behind `SearchClient`.
Missing `TAVILY_API_KEY` returns `discovery_unavailable` without a network
request. Search snippets select candidate URLs but are never passed to Judge
or stored as evidence. `FixtureSearchClient` provides the fully offline path.

## Product behavior

Claim status is one of `completed`, `agent_error`, `source_error`,
`budget_exhausted`, or `needs_human`. Document status is `complete`, `partial`,
or `failed`. Claim-level Miner, Scout, Judge, Challenger, source, and budget
failures are isolated so later claims continue. Global parse and artifact
failures terminate the document safely.

Each trace records `planned`, `dispatched`, `completed`, `failed`, and
`fallback` transitions using Agent names, claim IDs, and allowlisted codes.
Provider content, reasoning, headers, credentials, and unbounded webpage
content are not persisted.

The supported entry points are:

```bash
evidencetrace check <path>
evidencetrace check <path> --discover
evidencetrace check <path> --changed-from <git-revision>
evidencetrace check <path> --sarif evidencetrace.sarif
evidencetrace check <path> --suggest-patch suggestions.diff
evidencetrace demo
```

Suggested patches are deterministic unified diffs. The command never applies,
stages, or commits them. SARIF is still derived from canonical audit and
existing policy logic.

The GitHub workflow keeps minimum read/upload permissions. It captures a job
summary and uploads SARIF before propagating policy or partial status. Secrets
are optional, allowing fork PRs to run the deterministic path and report
skipped live capabilities.

## Offline demo

`evidencetrace demo` uses `examples/product-demo/README.md`, fixture search,
and fixture safe fetch. Its stable four-claim result is:

- cited ownership claim: `entailed`;
- uncited migration-date claim: Scout then `entailed`;
- numeric benchmark mutation: `contradicted`, with Challenger triggered;
- subjective recommendation: deterministic `not_checkable`, with no Scout or
  Judge call.

The document is `partial` because the offline Challenger abstains on one
low-confidence cited verdict, leaving that claim `needs_human`. The terminal
shows every claim status, Agent dispatch counts, skipped live model reason, and
remaining Coordinator/search/fetch budget.
